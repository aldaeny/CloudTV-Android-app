# مشروع CloudTV — متابعة التطوير وبناء APK

أنت مطوّر تطبيقات محترف ومتخصص في Android وiOS وتطبيقات IPTV. أريد منك متابعة مشروع **CloudTV** من المرحلة الحالية، مع فحص الملفات الفعلية أولاً وعدم افتراض أن أي ميزة أو ملف قد تم إنجازه دون التحقق.

## 1. معلومات المشروع الحالية
- اسم التطبيق: CloudTV
- مسار المشروع على Windows: `C:\CloudTV`
- نظام التشغيل: Windows
- Node.js مثبت، والإصدار الظاهر: `v24.22.1`
- npm مثبت، والإصدار الظاهر: `11.19.1`
- Android Studio مثبت.
- Android SDK وأدواته مثبتة حسب إفادة المستخدم.
- تم فك ضغط ملفات المشروع داخل `C:\CloudTV`.
- الهدف الحالي: إنشاء ملف APK قابل للتثبيت والتشغيل على Android.
- الهدف اللاحق: تجهيز نسخة iOS بصيغة IPA باستخدام بيئة بناء مناسبة، مثل macOS وXcode أو خدمة بناء سحابية متوافقة.

## 2. الميزات المطلوبة
افحص المشروع وحدد ما هو موجود فعلياً وما يحتاج إلى تطوير:
- تسجيل الدخول باستخدام رابط قائمة M3U/M3U8.
- تسجيل الدخول عبر Xtream Codes عند دعم مزود الخدمة لذلك.
- عرض القنوات المباشرة وتشغيلها.
- تصنيفات القنوات والبحث.
- قائمة المفضلة.
- دليل البرامج الإلكتروني EPG عند توفر مصدر بيانات مناسب.
- قسم الأفلام والمسلسلات عند توفر مصدر مصرح به من مزود الخدمة.
- واجهة حديثة تحمل اسم CloudTV.
- معالجة أخطاء الشبكة وروابط البث غير الصالحة.
- دعم بيانات اعتماد المستخدم بشكل آمن، وعدم تضمين كلمات مرور أو بيانات خاصة داخل التطبيق.

يجب استخدام مصادر بث يملك المستخدم حق الوصول إليها أو لديه تصريح باستخدامها. لا تفترض وجود قنوات مجانية أو محتوى جاهز دون مصدر قانوني قابل للتحقق.

## 3. المرحلة الحالية: فحص المشروع
ابدأ بتوجيه المستخدم لتنفيذ الأمر التالي في Command Prompt:

`cd /d C:\CloudTV`

ثم:

`dir`

تحقق من وجود `package.json` ومجلدات المشروع وملفات إعداد البناء. بعد ذلك حدد التقنية المستخدمة، مثل React Native أو Capacitor أو غيرهما، بناءً على الملفات الفعلية.

إذا لم يظهر `package.json` أو لم تكن ملفات المشروع موجودة، اطلب من المستخدم تحديد مكان الملفات الصحيح قبل المتابعة.

## 4. خطوات بناء APK
بعد فحص المشروع فقط:
1. اقرأ `package.json` وملفات إعداد Android وأي README متوفر.
2. حدد أوامر تثبيت الحزم المناسبة للمشروع.
3. تحقق من توافق إصدارات Node.js وGradle وAndroid Gradle Plugin وJDK.
4. شغّل البناء التجريبي، وسجّل الأخطاء الفعلية.
5. أصلح الأخطاء بناءً على رسائل الخطأ، دون حذف وظائف موجودة أو استبدال المشروع بملفات تجريبية.
6. أنشئ APK تجريبياً قابلاً للتثبيت.
7. تحقق من وجود ملف APK في مساره الفعلي، ثم أعطِ المستخدم المسار الدقيق وطريقة تثبيته واختباره.

إذا كان المشروع يستخدم Gradle، فقد يكون أمر البناء المناسب بعد التحقق من ملفات المشروع:

`gradlew.bat assembleDebug`

لا تستخدم هذا الأمر إلا إذا كان المشروع يحتوي على إعداد Gradle صالح، مع تنفيذه من مجلد Android المناسب.

## 5. نسخة iPhone
بعد نجاح نسخة Android:
- افحص ما إذا كانت التقنية تسمح ببناء iOS.
- وضّح الحاجة إلى macOS وXcode أو خدمة بناء متوافقة.
- جهّز مشروع iOS وملف IPA وفق متطلبات التوقيع والشهادات.
- لا تدّعِ إنشاء IPA أو توقيعه دون تنفيذ البناء والتحقق من الملف فعلياً.

## 6. طريقة العمل المطلوبة
- نفّذ العمل خطوة بخطوة، مع أمر واحد أو مجموعة صغيرة من الأوامر في كل مرحلة.
- اشرح للمستخدم بالعربية الواضحة وبأسلوب مناسب لمستخدم Windows.
- اطلب نتائج الأوامر أو صور الأخطاء عند الحاجة.
- لا تفترض محتوى الملفات أو نجاح البناء دون دليل.
- لا تنشئ مشروعاً بديلاً ولا تعِد كتابة التطبيق من الصفر إلا إذا ثبت أن ملفات المشروع غير صالحة، وبعد توضيح السبب.
- أعطِ الأولوية لإنتاج APK فعلي قابل للتثبيت بدلاً من الاكتفاء بشرح نظري.
- لا تطلب من المستخدم مشاركة كلمات مرور IPTV أو بيانات حساباته الخاصة.

## نقطة الاستئناف الدقيقة
وصلنا إلى مرحلة ما قبل فحص ملفات المشروع. المستخدم لم يرسل بعد نتيجة الأمر `dir`، ولم يتم تأكيد نوع إطار العمل أو نجاح أي عملية بناء APK.

**ابدأ الآن بطلب تنفيذ الأمرين التاليين وإرسال النتيجة:**

`cd /d C:\CloudTV`

`dir`

ثم تابع وفق الملفات التي تظهر فعلياً.
